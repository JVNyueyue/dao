# 文献池维护规范

用户可直接投喂原文、PDF、网页、书目或读书笔记，无需预先转换格式。收录的目标不是写泛泛摘要，而是建立能被后续田野分析准确检索和引用的理论记录。

## 资料状态

- `indexed`：仅完成书目信息和主题索引，尚未核验全文。
- `partially-read`：只阅读了明确列出的章节或页码。
- `verified`：已从可访问原文核验所记录的核心命题及定位。
- `user-notes`：只有用户笔记，尚未与原文核对。

状态不得夸大。只有摘要或二手转述时，不标记为 `verified`。

## 单条记录格式

```yaml
id: 可稳定引用的短标识
type: book | article | review | chapter | notes | webpage | other
title: 题名
author: 作者或机构
year: 年份；未知则留空
source: 文件名、URL、数据库或用户消息
locator: 已阅读或引用的页码、章节、段落或网页小节
status: indexed | partially-read | verified | user-notes
analysis-track: Q-case-centered | A-theory-building | hybrid
concepts:
  - 核心概念
disciplines:
  - 学科或研究领域
topics:
  - 主题与研究对象
methods:
  - 研究方法或材料类型
claims:
  - 可由资料核验的理论命题
argument:
  question:
    - 作者试图回答的具体问题
  opponents:
    - 作者反对、修正或区别于哪些观点
  steps:
    - 论证步骤及各步骤之间的推理关系
  evidence:
    - 每一步使用的材料、比较或方法
  conclusion:
    - 作者最终能够推出的结论
  warrants:
    - 从材料到结论所依赖的中间理由
  alternatives:
    - 作者处理过或遗漏的替代解释
cases:
  - name: 案例名称
    context: 时间、地点、行动者和材料性质
    role: 例证 | 概念生成 | 机制证明 | 反例 | 边界测试 | 历史追踪 | 方法示范
    supports: 案例具体支持哪一步论证
    cannot-support: 案例不能证明什么
scope:
  - 命题适用的对象、条件或历史语境
limits:
  - 作者承认的限制，或文本中明确可见的边界
relations:
  - 与池中其他理论的继承、争论或差异
traditions:
  - 理论谱系或学术传统
field-dialogue:
  - 可能与哪些田野问题对话；仅作检索线索，不作预设结论
quotes:
  - 必要的短引文及页码或段落定位
```

`analysis-track`按[文章拆解分流规范](article-analysis-routing.md)判断。它描述文章如何承担主要论证负荷，不是对文章学术价值的高低排序。经验论文可以推进理论，理论论文也可以使用案例；关键在于案例是否构成全文的主要讨论对象。

## 文献记录与理论记录分离

文献入池不等于理论已经入池。每篇论文、专著、书评或综述先建立“文献记录”；当某一理论已经取得原著并完成核心章节核验后，再建立独立“理论记录”。同一理论可关联多篇原著、批评和经验研究，但不得以综述条目替代理论原典。

理论记录至少包含：

```yaml
id: theory-稳定短标识
type: theory
name: 理论或分析框架名称
originators:
  - 原始提出者或关键奠基者
primary-sources:
  - 已核验原著、版本、章节和页码
status: indexed | partially-read | verified
problem:
  - 理论最初试图解决的问题
core-concepts:
  - 概念、原文定义与定位
propositions:
  - 概念之间的关系、机制或因果命题
genealogy:
  - 理论的上游来源与同期争论
developments:
  - 后续继承、修正、批评和经验检验
cases:
  - 原作者及后续研究使用的案例
argument-structure:
  - 原始问题如何被分解，各概念在论证中承担什么功能，作者怎样从证据推进到命题
case-logic:
  - 案例是产生概念、证明机制、展示变异、构成反例还是限定外推
applications:
  - 适合分析的问题、对象和尺度
scope:
  - 成立所依赖的社会、历史、制度与方法条件
limits:
  - 反例、失败场景和不可外推范围
relations:
  - 与理论池中其他理论的互补、竞争或不可通约关系
secondary-leads:
  - 尚未回到原著核验的二手线索
```

## 原文术语与翻译

理论和概念记录默认保留以下三联信息：

```yaml
terms:
  - original: 作者使用的原文词或短语
    literal-translation: 尽可能直接的中文翻译
    adopted-translation: 本理论池采用的译名
    source: 原著、版本、页码或章节
    note: 与其他常见译法的差异及使用理由
```

- 不得只记录中文概括而丢失原文词形；概念存在多种语言版本时，分别注明。
- “直译”用于显示原词构造，不一定是最后采用的学术译名。
- 引用原文只保留定义性短句或关键词组，避免用长引文替代分析；必须注明页码或章节。
- 二手文献提供的原文词只能作为检索线索。没有回到原著时标记“二手定位/原文待核”，不得把二手译名当作作者定译。

## 理念转型记录

“实践转向”“身体转向”“情感转向”“物转向”“流动转向”等不是单一理论，而是研究对象、解释单位、证据观或方法论发生变化的理念转型。应单独建立`intellectual-turn`记录，至少包括：

```yaml
type: intellectual-turn
name: 转向名称
original-terms: 原文名称及不同版本
from: 所反对、修正或移开的研究取向
to: 新的对象、分析单位、证据和问题意识
key-authors: 不同版本的关键作者
primary-sources: 已核验原著
theories-under-turn: 该转向下彼此不同的理论
methodological-consequences: 对田野、材料和写作方法的影响
limits: 转向叙事遮蔽的连续性、内部差异及不可外推范围
status: indexed | partially-read | verified
```

不得把“转向”当作能直接解释材料的中层机制。写作时应先说明它改变了怎样的问题意识，再调用该转向内部已经核验的具体理论和概念。

只有 `primary-sources` 中的关键命题已经回原著核验，且概念定义、命题关系和适用边界均有定位时，理论记录才可标为 `verified`。只有作者姓名、理论名称或综述概括时标为 `indexed`；只核验部分原著章节时标为 `partially-read`。

## 论证逻辑与案例功能

收录不能停在“作者提出了哪些概念”。每部文献还要建立论证图：

1. 作者从什么经验或理论困难出发；
2. 作者把问题拆成哪些子问题；
3. 哪些概念是前提、分析工具、中介机制、结果变量或规范判断；
4. 作者反对谁，保留了对方的什么，又修正了什么；
5. 每一步使用什么证据，证据怎样支持下一步；
6. 结论比材料多走了多远，是否存在未处理的替代解释；
7. 案例在论证中承担什么功能。

案例不得只记录题名。至少记录时间、地点、行动者、实践过程、材料来源及其论证角色。同一案例可能承担多种功能，但需要分别说明。例如：

- `概念生成`：作者从案例中提出新的分析单位；
- `机制证明`：案例显示若干概念如何连接；
- `反例/失败案例`：推翻线性命题或显示必要条件不足；
- `边界测试`：说明理论在哪些条件下失效；
- `历史追踪`：展示概念或实践怎样发生变化；
- `方法示范`：展示如何观察、比较或解释材料。

后续调用理论时先匹配“问题结构与机制”，再比较案例结构，最后才检查概念名称的表面相似性。不得因为田野材料中出现同一个词，就认定理论适用。

具体文献记录须依文章类型执行Q1—Q3或A1—A4，字段、空项规则及混合文章处理见[文章拆解分流规范](article-analysis-routing.md)。

## 二手综述与概念应用研究

二手综述不是低价值的原典替代品，而有独立的学术史功能。对综述建立`review-map`记录，保存：

- 综述划定的时间范围、学科范围和问题边界；
- 它怎样分期、分类并命名理论阵营；
- 它选择了哪些关键作者，遗漏了哪些传统；
- 它认为思想变化由什么问题、材料或制度推动；
- 它怎样描述继承、分歧、断裂、转向和本土化；
- 综述作者自己的判断，与被综述作者的原始主张分别记录；
- 可用于定位哪些原典、关键词、争论和后续研究。

综述可以支持“学界如何叙述某理论的发展”“某概念在中文学界如何被接受”等学术史判断；不能独自支持被综述理论的定义与命题。若不同综述给出不同谱系，应并列保存，不能强行合成唯一历史。

学者没有创造概念但把概念迁移到新材料时，建立`application-study`记录：

```yaml
type: application-study
borrowed-concept:
  original-theorist: 概念原作者
  original-source: 已核验原典
  original-problem: 原概念处理的问题
application:
  applying-author: 应用者
  new-case: 新案例
  transfer-bridge: 作者怎样证明案例与原理论可比
  operationalization: 抽象概念被转化成哪些可观察材料
  argument-role: 概念在文章中承担前提、机制、比较、反例或修正中的哪种功能
  transformations: 作者删减、扩展、重命名或重组了什么
  writing-moves: 理论进入田野段落的具体论证动作
portability:
  reusable-conditions: 迁移成功所依赖的条件
  nonportable-elements: 与该案例绑定、不可照搬的部分
  possible-new-domains: 可尝试迁移的新对象
  verification-needed: 再迁移前需补什么证据
```

概念应用研究既可作为经验研究直接引用，也可作为写作与方法范例。但应用者对概念的改写必须归给应用者，不能反投射为原理论家的命题。

缺失字段保持为空或写“未知”，不可推测补齐。用户对理论的解释记为 `user-notes`，与作者主张分开；两者冲突时指出差异。

## 存储约定

- 总目录使用 `references/library/INDEX.md`。
- 每条理论资料用独立 Markdown 文件保存，文件名采用 `作者-年份-短标题.md`；作者或年份未知时使用可辨识的稳定名称。
- 跨文献的理论谱系、应用场景、适用边界和原典缺口统一维护在 `references/library/THEORY-MAP.md`；该文件用于导航，不替代独立理论记录和原典核验。
- 原始附件若不能放入文献池，记录其实际文件路径或稳定 URL。
- 资料被替换或精读范围扩大时，更新状态和定位，不重复创建同一条记录。

## 检索维度

不只按概念名检索，还应按学科、研究对象、方法、社会关系、行动机制、因果主张、时序、尺度、制度条件、失败案例、理论谱系、学术争论和适用边界检索。建立候选后，回原文核验；不能仅凭标题、摘要或搜索片段断言理论主张。

## 用户可选投喂格式

```text
资料名称：
作者与年份：
来源、文件或链接：
我关注的概念：
我理解的核心观点：
重要段落或页码：
希望与哪些材料对话：
```
